# Fix plan from the October 2-3, 2026 evaluation

Work items for a fresh Claude session (written for Opus 5.5), derived from `docs/EVALUATION-2026-10-02.md` (15
areas, 62 verified findings). Each item is self-contained: what is wrong, where, what to change, how to prove it.
Finding numbers (H1, M4, ...) refer to that file.

## Ground rules for the session

- Read `CLAUDE.md`, `docs/HISTORY.md` ("How the work is done now") and `docs/TESTING.md` first. Follow the loop:
  test build labelled above v1.11.1 (`v1.12.0-fix.N` in `version.txt`, touch `CMakeLists.txt`), flash with
  `python tools/harness/harness.py --flash build/v55/weather_amoled.bin`, prove on the device, let the user try it,
  then "document and commit". Claude may tag and test rc releases (`harness.py --ota vX`); a **stable** release
  needs the user's OK. New behaviour → minor bump: the next stable is **v1.12.0**.
- Check that nobody else is using the board (`flash.status`, `serial_live.txt` timestamps) before flashing.
- Page changes: `cd tools/webtest && npm test` and look at `shots/` before building firmware.
- New display text goes in `main/i18n_strings.h` (en, fr, iu) and page text in `I18N` in `main/web/index.html`.
  French is Québec standard written French; check fit with snapshots, including `settings1..3`, `phone`, `setup0/1`.
- Every bug fix gets a test (harness, Playwright or a host test). A general lesson goes in `CLAUDE.md`.
- After changing `sdkconfig.defaults`, delete `build\v55\sdkconfig` and reconfigure.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` unless the user says otherwise.
- `.github/` cannot be written by the remote file tools; on the PC it can.
- Four decisions belong to the user (evaluation questions 1, 2, 3, 7). Items that depend on them say so; do
  everything else first and ask at the right moment, not up front.

Sizes: S < 1 h, M = a few hours including device proof, L = a session. Groups are ordered by value; items inside a
group are independent unless stated.
